# 参考插件审阅：毛熊上架宝 0.3.14（子代理报告摘要）

来源：只读审阅子代理的报告，我没有逐行复核。插件主体为混淆压缩代码，很多结论只有关键词依据。只借鉴思路，不复制代码（混淆的商业发布包，授权状况未知）。

## 它是什么

MV3 插件，覆盖 采集 → AI 生图和文案 → 上架 全链路，支持 1688、淘宝、拼多多、ozon.ru。Ozon 映射、AI、提交都走它自家后端（creative.thebear.cn），店铺凭据交给后端保管。权限很重（debugger、<all_urls>）。

## 值得借鉴的思路

1. 页面内嵌 JSON：在页面主世界读取，白名单只取标量字段，限制数量，并用 URL 中的 offerId 交叉校验，冲突就报错。
2. SKU 价格可追溯：每个价格记录来源字段和原始值，缺价的 SKU 明确列出，不静默补值。与我们"未知留空待人审"一致。
3. 多路径互相验证：规格和价格从三处内嵌数据互补读取，冲突时报错。
4. 描述文本：从详情文档 URL 再 fetch 一次，限制 HTTPS、域名白名单、超时和大小上限。具体 URL 在页面数据的哪个路径：未确认。
5. 图片按用途分字段：主图、详情图、规格图分开输出。
6. 品牌：依次尝试 JSON-LD、DOM 选择器、内嵌对象、属性表里名为"品牌"的行。
7. SKU 级件重尺寸：页面数据里有按 SKU 给出的重量和长宽高（pieceWeightScale），可能解决"重量和包装尺寸只能人工填"的问题。覆盖率未确认。
8. 属性分类：系统托管、技术标识符（不填）、URL 型、必填自然语言。可作为我们"不要填"名单的参考。
9. 预检分级：必填缺值阻断，评分类属性缺值只提示。印证"不是只处理必填项"。
10. 字典匹配：精确匹配，不命中留空待审。与我们一致。

## 反面教材，不照搬

- debugger 加 <all_urls> 权限过重，处处是"debugger 被占用或断开"的补丁。
- 用宽泛 URL 关键词筛网络响应，易误抓。
- 页面结构一变路径就失效，所以堆了四层兜底，复杂度高。
- 允许 LLM 或视觉模型做属性映射，与我们"AI 只做自由文本和图片"的原则冲突。
- 依赖外部后端托管 AI 和店铺凭据。
- 完全混淆，不可审计。
