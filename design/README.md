## 核心设计决策汇总

### 1. 产品定位
- **批量快速上架**，每天处理几十到上百个商品
- 速度优先，准确率可适度牺牲
- 后续可在Ozon后台补充调整

### 2. 工作流程
```
选Ozon类目 → 输入1688关键词 → 自动抓取50个商品 
→ 规则处理 → 人工处理阻断项 → AI生成 → 批量提交
```

### 3. 阻断策略
**只在以下情况阻断**：
- 必填属性缺失
- 变体属性无法映射（颜色、尺码）
- 价格未设置
- ~~分类未确认~~（已前置解决）

### 4. 数据映射
**混合模式**：
- **人工规则**：必填属性、变体属性（颜色、尺码、品牌、性别）
- **AI处理**：俄文标题、描述、颜色名称（10097）。第一阶段图片只原样上传 OSS，不做 AI 处理；可选属性留空，不由 AI 推断

### 5. 规则组织
**类目级复用**：
```
rules/
├── categories/
│   ├── women-apparel/  # 女装（连衣裙、T恤等共享）
│   ├── men-apparel/    # 男装
│   └── kids-apparel/   # 童装
└── types/              # 类型特殊处理（覆盖类目规则）
```

### 6. AI调用时机
**通过阻断后才调用AI** - 避免为失败商品浪费成本

### 7. 重复商品处理
**基于状态智能处理**：
- 已上架/审核中 → 跳过
- 待处理 → 更新原始数据，保留人工修改
- 已放弃 → 重新激活

## 规则编写工作量

### 初期投入
- 女装规则：约90条（品牌50 + 颜色30 + 尺码10）
- 男装规则：约90条
- 童装规则：约80条
- **总计**：约260条规则
- **时间**：1-2周

### 维护成本
- 新增Ozon类型：只需在映射表添加一行
- 新增规则类目（如鞋类）：约80-100条规则
- 调整现有规则：一次修改，整个类目生效
