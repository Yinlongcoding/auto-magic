# 已确认中文 → 显式引用链 → valueId

更新：2026-10-09。最新授权范围：类型清单只保存属性与路径；字段绑定、转换、默认值和值映射全部迁入 `common` 或 `dictionary`。字典入口可以进一步引用公共字典。

## 当前流程

产品详情事实 → 清洗 → 目标 Schema → 类型引用清单 → 字段模块生成方案 → 人工确认 → 沿字典引用链精确匹配 → 输出结果。

是否需要 valueId 由目标 Schema 的 dictionaryId 决定。普通文本保留确认值，无 valueId；字典字段从最终配置表查询选项。路径只定位表，不能代替确认内容。

## 实际性别示例

[类型 93182 清单](../../rules/categories/200000933/types/93182.json)包含：

```json
{ "id": 9163, "path": "dictionary.320.93182" }
```

读取 [字典入口](../../rules/dictionary/320/93182.json)，使用其中的来源绑定和原有“女性”默认值生成待确认内容。该入口限定当前连衣裙品类／类型；原默认值不会扩散为所有服装的默认性别。

人工确认“女性”后，入口的 `valuePath="common.gender"` 指向 [公共性别字典](../../rules/common/gender.json)。最终精确匹配 `displayZh="女性"`，得到 `targetValue="женский"`、`valueId=22881`。

```text
types/93182.json
  └─ 属性 9163 → dictionary.320.93182
                    └─ valuePath → common.gender
                                      └─ “女性” → 22881
```

`9163` 为当前已核验属性 ID，`320` 为字典 ID，`22881` 为具体选项 ID。用户讨论中的其他属性编号仅为示意，不能替换真实 Schema。

## 查询与引用规则

- 只执行类型清单声明的属性和引用，不扫描公共目录，不自动继承或覆盖。
- 字段模块可以保存本地值，或用 valuePath 指向值字典；引用和本地值互斥。
- 值字典也可指向下一份值字典，最多 8 个节点。检测循环、断链、属性／字典 ID 不一致和不适用状态。
- 查询词为确认中文去除首尾空白后的原文，与 displayZh 精确匹配。未知、歧义、禁用或低可信值留空，不翻译或推算。
- 字典引用失效时保留确认内容，让 targetValue/valueId 留空；配置结构错误则明确报错、清除旧结果。
- 集合型属性当前每个共享分组只匹配一个值；不拆分复合输入、不生成多值列表。复杂属性不支持。

路径的目录映射、完整字段与字典 JSON 格式、维护操作见 [规则说明](../../rules/README.md)。JSON Schema 为 [类型清单](../../rules/type-field-plan.schema.json)及[模块](../../rules/field-module.schema.json)。

## 更新与结果

补充最终字典中的值映射后直接重新匹配；各引用重新读取，无需重启。导出前也重新匹配。修改绑定或引用需要重新生成方案，防止旧来源确认继续生效。

导出保留来源事实、SKU 范围、confirmedValue 和字段生成方式，新增 modulePath、valueSourcePaths、targetValue、valueId、valueResolution、valueStatus。全部字典字段分组有 ID 时 dictionaryResolved=true；该标记仅表示本地匹配完成，不代表官方在线校验或上架成功。

## 本次规则行为变更

此前按公共 → 品类 → 类型合并值规则，字段绑定存放在品类／类型文件；现在类型只保存显式引用，绑定、转换、默认值及值映射全部移至模块，沿声明的链路查询，不使用隐式兜底。

原有 13 个绑定、性别 4 个 ID、款式 28 个 ID及现有默认／转换／分组策略保留。原款式值规则的来源标签现作为第 14 个模块的绑定保存，因非必填暂不执行。颜色和俄罗斯尺码仍没有可执行值 ID，不自动补造。

旧规则完整快照和 reviews.db 历史保留，旧在线候选查询、学习回写及隐藏表单移除。新策略使用独立审核身份，旧统计不直接继承。验证覆盖新引用链、旧绑定行为和数据保存；不请求 Ozon 上架。
