# Ozon 运营字段与俄罗斯尺码策略

## 合并至一张卡片（属性 8292）

“合并至一张卡片”不是商品的事实属性，也不是“组合形式=单件”的同义词。它表示 Ozon 前台是否把同一商品的多个变体合并到一个商品卡片下展示，例如颜色、尺码或容量作为同一张卡片的变体。

当前阶段的处理规则：

1. 先按 Ozon Schema 将该字段标记为 `policy_required`。
2. 不引用 1688 标题、详情或 SKU 事实作为该字段证据。
3. 等应用层明确策略后再编译发布参数。建议默认策略为“按可售 SKU 的变体维度合并”，但只有在确认 Ozon 当前接口字段和商家运营意图后才落地。
4. 没有策略时禁止让 Qwen 猜测，也禁止因为商品只有一个 SKU 就自动选择某个字典值。

## 俄罗斯尺码（属性 4295）

国际尺码 `S/M/L/XL` 不能直接当作俄罗斯尺码提交。不同供应商的版型、男女装和测量方式会导致同一字母对应不同的胸围、腰围或臀围区间；因此当前仅有字母尺码时必须保持 `conversion_required`。

需要特别区分“规则行”和“商品最终值”：规则表中的一行只负责转换一个源 SKU 尺码，商品最终结果应保留所有 SKU 的映射集合，而不是压缩成一个尺码。例如女装连衣裙应保持 `S→42、M→44、L→46、XL→48` 四条关系。

推荐的可审计转换流程：

1. 从 1688 详情中提取尺码表，而不是只提取 SKU 的字母标签。优先读取胸围、腰围、臀围、衣长等厘米数值，并记录原始 `factId`。
2. 将表头、单位和数值统一为厘米；无法确认单位、测量部位或数值范围时，标记为待人工确认。
3. 维护版本化的俄罗斯尺码规则表，至少按服装类型、性别、测量部位和区间记录。规则表不是 Qwen 的常识推断，必须由应用配置或用户确认提供。
4. 对每个 SKU 独立用区间匹配得到候选俄罗斯尺码；若多个区间命中、只有字母尺码、或详情缺少关键测量值，则不自动发布，返回 `conversion_required` 或 `ambiguous`。
5. 将每个 SKU 的原始尺码、采用的规则版本、命中的区间和最终 Ozon `valueId` 一并保存，便于复核和后续映射方案库复用。

首版建议：先实现“尺码表事实提取 + 规则表接口 + 自动规则集选择”。系统应根据已确认的 Ozon 类目/类型、性别证据和源尺码单位自动选择规则集；只有无法唯一判断时才请求人工确认。暂不内置跨品类通用 `S→42` 等固定换算。

本次收到的参考表已录入 `RussianSizeRuleCatalog`（版本 `ru-size-reference-2026-09-02.v1`），范围如下：

- 女装上衣/连衣裙/外套：`S/M/L/XL/2XL/3XL → 42/44/46/48/50/52`，并保留胸围、腰围、臀围参考值。
- 女裤/半身裙：`26/27/28/29/30/31 → 40-42/42-44/44-46/46-48/48-50/50-52`，并保留腰围、臀围区间。
- 男装上衣：`M/L/XL/2XL/3XL/4XL → 46/48/50/52/54/56`，并保留胸围、领围参考值。
- 女鞋：`225/230/235/240/245/250mm → 35/36/37/38/39/40`。
- 男鞋：`245/250/255/260/265/270mm → 39/40/41/42/43/44`。
- 童装：身高区间 `98-104/110-116/122-128/134-140/146-152cm → 30/32/34/36/38`。

这些表是当前测试用参考规则，不代表所有供应商的版型；规则集选择属于应用内部决策，不能把相同字母尺码跨女装、男装或鞋类全局复用。必要时可以提供高级覆盖入口，但不应成为正常流程中的必填选项。

## 与 Qwen 的边界

- Qwen 负责识别事实、提出文本候选和标记依赖。
- Ozon 字典接口负责提供真实 `valueId` 候选；本地只做保守的精确归一化。
- 应用确定性代码负责合并卡片策略、尺码换算和最终发布编译。
- 任一依赖未解除，都不得把映射标记为可直接发布。
