# Auto Magic 1688 Collector

当前开发版本：`v0.1.23`

> 开发约定：凡修改 `plugin` 内的运行逻辑或界面，必须递增 `manifest.json` 版本号，并在交付说明中明确写出新版本。插件弹窗右上角显示 Chrome 当前实际加载的版本。

## 当前采集流程

1. 在用户当前 Chrome 中复用或创建 1688 搜索页。
2. 应用采购价区间与排序，滚动加载商品列表，最多保留 60 条原始列表记录。
3. 按列表顺序串行采集详情，同一时间只使用一个共享详情标签页。
4. 每次访问前检查共享标签页；标签页丢失时自动重建并重试当前商品。
5. 详情页不等待浏览器报告完整加载；DOM 可用后立即读取标题、属性、图库和页面结构化 SKU，单条总预算为 30 秒。
6. 只有属性缺失，或页面存在 SKU 证据但没有确认组合时，才滚动到对应属性/SKU 区域并重试；第一阶段不滚动到页面底部。
7. 优先从页面初始化脚本、动态商品状态、React 页面状态及 `data-*` JSON 中读取明确的 SKU 组合；若只有完整规格轴，则枚举规格轴的笛卡尔积作为待核实 SKU 组合，标记 `dimension-cartesian`，价格和库存保持未知。明确的稀疏 SKU 列表不会被补全。
8. 每完成一条详情，写入 Chrome 本地进度并向 AM 发送进度心跳。
9. 验证码、网络错误、加载超时、标签页丢失和渲染不完整等失败先进入二次采集队列。
10. 首轮结束后统一等待 5 秒，再按原列表顺序串行执行二次采集。
11. 成功详情按 `offerId + 采集器缓存版本` 缓存，忽略 URL 中会变化的 `uuid`、`sourceId` 等参数。

详情结果中的 `facts` 是唯一的规范属性集合。`raw` 不再重复保存标题、属性和颜色派生列表，只保留结构化 SKU、图库及兼容审计文本；采集策略和选择器统计放在 `diagnostics`。已明确识别的“颜色/规格 × 重量或尺寸”矩阵不会被拆成普通属性事实。

来源可追溯且规格结构完整的真实组合进入 `raw.skuCombinations`。采集层不猜测规格语义：`9号`、`11号`、`均码`、`大码`、`36键`等原始值均可保留，交给后续品类规则判断；库存为 0 的真实组合也保留，并记录 `stock: 0`、`availability: unavailable`。

只有规格轴推导组合时，详情状态为 `partial`，但组合可进入属性映射；逐组合库存、价格和可售性仍待核实。没有可用组合时也保持 `partial` 并输出警告。

测试阶段仍只处理列表前 10 条详情；列表输出上限仍为 60 条。

## 安装与更新

1. 打开 `chrome://extensions/`。
2. 开启“开发者模式”。
3. 首次安装时选择“加载已解压的扩展程序”，目录为 `D:\ys-project\auto-magic\plugin`。
4. 更新源码后在扩展卡片上点击“重新加载”。
5. 打开插件弹窗，确认右上角版本为 `v0.1.23`。

## 运行要求

- 仅访问 `*.1688.com`。
- 同一时间只运行一个采集任务。
- 需要保持 1688 正常登录并使用稳定直连网络。
- 不自动处理或绕过验证码。
- 1688 页面结构变化后，需要更新 `content/detail-extractor.js` 与相关选择器。
